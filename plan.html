Docusaurus Structural Layout Plan

1. Overall Codebase Structure

The Docusaurus project is initialized in a dedicated directory (e.g., docsite/) to separate it from the main Go codebase, ensuring a clean monolithic repository structure.

  • /docsite/docs/ - Primary documentation MDX files (Public).
  • /docsite/contributing/ - Contributor and development documentation MDX files (Internal/Separated).
  • /docsite/src/ - Custom React components and styling.
  • /docsite/static/ - Static assets like images and custom text files (e.g., llms.txt).
  • /docsite/docusaurus.config.ts - Core site configuration.

2. Custom Theming & Tailwind CSS

We will implement custom theming utilizing Tailwind CSS.

  • SEO Friendliness: Tailwind CSS is fully SEO-friendly in Docusaurus. Classes are compiled into static HTML and CSS at build time.
  • Light/Dark Mode: Tailwind's dark: variants will be configured to work smoothly with Docusaurus's native color mode toggling.

3. Reusable Component Design

We will establish a dedicated UI component library for documentation pages.

  • Component Architecture: Highly reusable primitive components (e.g., Button, Input, Card, Alert) will be created inside src/components/ui/.
  • Styling: These components will be styled with Tailwind CSS utility classes.

4. Content Strategy (MDX)

For all standard documentation contexts, we will exclusively use MDX (.mdx) files to seamlessly blend standard Markdown for readability with JSX/React components.

5. Search Capabilities

We use the @easyops-cn/docusaurus-search-local plugin to provide offline-capable, fuzzy search. We can configure this plugin to index both primary and contributor document instances separately or together depending on search visibility requirements.

6. Multi-Instance Documentation (Separating Contributing/Development Docs)

To keep contributor documentation (like local development setup) completely isolated from the primary docs (so they do not share the same sidebar or root URL), we will use Docusaurus Multi-instance plugins.

File System Structure

The development section will live strictly as a nested category under the isolated contributing documentation instance:

docsite/
├── docs/                     # Primary Docs (e.g., docs.domain.name/)
│   ├── quickstart.mdx
│   └── advanced-setup.mdx
├── contributing/             # Contributing Docs (Isolated - e.g., docs.domain.name/contributing/)
│   └── development/          # Nested development section
│       ├── commands.mdx
│       ├── docker-dev.mdx
│       └── hook-operator-test.mdx
├── sidebars.ts               # Controls sidebar for Primary docs
└── sidebarsContributing.ts   # Controls sidebar for Contributing docs

7. LLM Accessibility (llms.txt)

To provide rich context for AI agents and LLMs crawling the sites, we will serve llms.txt and llms-full.txt at the root of both documentation instances.

Because Docusaurus directly copies everything in the static/ directory to the final build root, we can easily achieve this by mapping the folders accordingly:

docsite/
└── static/
    ├── llms.txt                 # Served at docs.domain.name/llms.txt
    ├── llms-full.txt            # Served at docs.domain.name/llms-full.txt
    └── contributing/
        ├── llms.txt             # Served at docs.domain.name/contributing/llms.txt
        └── llms-full.txt        # Served at docs.domain.name/contributing/llms-full.txt

This ensures LLMs looking at the primary site get user-focused context, while LLMs looking at the contributing site receive developer-focused architecture context.

8. Internationalization (i18n) & Multilingual Support

To support multiple languages while maintaining optimal SEO, we will leverage Docusaurus's native i18n configuration. We will configure the following locales:

  • English (en) - Default
  • German (de)
  • French (fr)
  • Japanese (ja)
  • Russian (ru)

This will be configured in docusaurus.config.ts like so:

i18n: {
  defaultLocale: 'en',
  locales: ['en', 'de', 'fr', 'ja', 'ru'],
}
  • Static Site Generation (SSG): Docusaurus generates completely distinct, static HTML builds for each locale (e.g., /de/, /ja/). Search engines index these static paths effortlessly, avoiding client-side routing issues.
  • SEO & hreflang Tags: The framework automatically injects <html lang="..."> attributes and <link rel="alternate" hreflang="..."> tags into the <head> of every page across all five languages.
  • Folder Structure: Translated markdown files will reside in their respective directories (e.g., i18n/de/docusaurus-plugin-content-docs/current/) and map 1-to-1 with the primary English files in docs/.
  • Navigation UI: A dropdown language switcher component will be added to the navbar (via type: 'localeDropdown'), allowing users to easily switch between the 5 supported locales.
